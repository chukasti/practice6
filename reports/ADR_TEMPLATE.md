# ADR-001. Управление приоритетами каскада

**Статус:** принято · **Дата:** 2026-11-18 · **Автор:** студент ИСИТ-4, ветка `fix/css-architecture`

## Контекст

После слияния продуктовой команды Atlas UI и подрядчика в одном документе сосуществуют два авторских CSS: компонентная библиотека (7 семейств) и vendor-виджет закупок. Два конкретных конфликта, зафиксированных в DevTools (computed styles):

1. `#workbench .ui-button { background:#2939a8 }` (legacy.css, **unlayered**) перебивает `.ui-button--primary` из `@layer components`: unlayered normal-правила стоят выше именованных слоёв, специфичность не успевает сравниться (baseline: `rgb(41,57,168)`).
2. `@layer states { .is-danger { background:#c12236; color:#fff } }` перекрашивает `.ui-tag--danger` и `.ui-alert--danger`: поздний слой + одинаковая специфичность 0-1-0 → глобальный служебный класс выигрывает у модификаторов семейств.

Дополнительные ограничения: vendor CSS удалять нельзя; `!important` добавлять нельзя; тесты менять нельзя; нативная семантика (checkbox, dialog, disabled) обязательна.

## Рассмотренные варианты

| Альтернатива | Плюсы | Риски | Почему выбрали или отклонили |
|---|---|---|---|
| A. Всё в одном CSS-файле | Нет накладных расходов на импорты; простая доставка | Любое правило может перебить любое: порядок = единственный регулятор; vendor CSS неизбежно конфликтует; дубли и «последний выиграл» не диагностируемы | Отклонено: не изолирует vendor и не даёт управляемого приоритета — именно этот режим мы и наблюдали в baseline |
| B. БЭМ + регламент селекторов | Строгие имена `block__element--modifier`; нулевой порог входа; работает во всех браузерах | Регламент не исполняется браузером: один `#id` или `.card .button` из другого файла всё равно победит; vendor CSS не подписывает наш конвеншен; конфликты обнаруживаются только ревью | Частично принято: БЭМ-нейминг оставлен как **договор именования**, но не как механизм приоритета |
| C. @layer + токены + контракт компонента | Приоритет управляется декларацией слоёв, а не порядком селекторов; vendor изолируется импортом `layer(legacy)`; смена темы = смена токенов без правки компонентов; инварианты проверяются статическими тестами | Нужны современные браузеры (все evergreen поддерживают @layer с 2022); дисциплина: unlayered-импорт мгновенно ломает приоритет; `!important` внутри слоёв меняет порядок на обратный — требует запрета | **Принято**: единственный вариант, где «кто победит» выводим из архитектуры, а не из порядка файла |
| D. Только CSS Modules | Стиль компонента локален по построению; хэши имён исключают коллизии | Токены, темы, глобальные reset и vendor CSS всё равно глобальны; требует сборщика, а стенд — zero-build; vendor CSS не модульный; каскад скрыт, учебная цель «управлять каскадом» теряется | Отклонено для этой заготовки: избыточная инфраструктура; аргументы зафиксированы как «против» именно для zero-build стенда |

## Решение

**Порядок слоёв** (неизменен из baseline, `css/app.css`):

```
@layer reset, legacy, tokens, base, components, states, utilities;
```

Обоснование порядка: `reset` раньше всех — низкоприоритетная нормализация; `legacy` — vendor CSS **обязан** проигрывать библиотеке при normal-важности, поэтому импортируется вторым (`@import url('./legacy.css') layer(legacy)`); `tokens` после legacy, чтобы переменные темы перекрывали возможные переменные подрядчика с теми же именами; `base` — каркас страницы; `components` — структура и варианты семейств; `states` позже `components`, чтобы hover/focus/active/invalid/disabled переопределяли вариантные значения без роста специфичности; `utilities` последним — точечные атомарные правки (`u-visually-hidden`, полноширинные кнопки на узких экранах).

**Принцип специфичности:** внутри библиотеки селекторы не превышают 0-2-0 (класс + псевдокласс); ID запрещены; селекторы потомков только через прямое владение (`>`) или явные слоты `__`; служебные глобальные классы состояний (`.is-*`) запрещены — состояние выражается псевдоклассом или ARIA-атрибутом своего семейства. `:where()` применён в reset/base для обнуления веса; `:has()` — только в области одного компонента (`.ui-field:has(input[aria-invalid='true'])`).

**Публичные классы и модификаторы** (контракт):

- Кнопка: `.ui-button` (единственный базовый блок) + `--primary | --secondary | --ghost | --danger` × `--sm | --lg` (размер по умолчанию md); состояния: `:hover`, `:focus-visible`, `:active`, `:disabled` (нативный атрибут).
- Тег: `.ui-tag` + `--neutral | --success | --warning | --danger`; состояний нет (неинтерактивен).
- Поле: `.ui-field` (+ `--full` для grid-растяжения), слоты `label`, `input`, `textarea`, `__hint`, `__actions`; состояние ошибки — `aria-invalid="true"` на контроле, выставляемый JS после blur/submit.
- Карточка: `.ui-card` + `--featured`; слоты `__meta`, заголовок `h3`, `__description` (или прямой `> p`), вложенные компоненты не стилизуются.
- Уведомление: `.ui-alert` + `--info | --success | --warning | --danger`; слоты `strong`/`p` и `__dismiss` (кнопка с `aria-label`).
- Переключатель: `label.ui-switch` со слотами `__copy`, нативный `input[type=checkbox]` (visually-hidden) + `__track`/`__thumb`; состояния `:checked`, `:disabled`, `:focus-visible` (обводка на треке).
- Диалог: `dialog.ui-dialog` + `__head`, `__actions`; открывается только `showModal()`; `aria-labelledby="dialog-title"`.

**Зависимость от селекторов родителя:** запрещена. Ни один компонент не зависит от `#workbench`, `.hero` или иного контейнера: один и тот же HTML выглядит одинаково в любом месте (проверено сценариями #26 матрицы — padding тега в карточке и вне её совпадает).

**Third-party CSS:** любой новый vendor-файл подключается **только** через `@import ... layer(legacy)` (или отдельный ранний слой, объявленный в app.css). Внутри vendor-файла правила ограничены его областью (`.legacy-widget …`): подрядчик стилизует свой виджет, но не теги `button`/`input` и не классы `.ui-*` глобально. `!important` в vendor запрещён регламентом и проверяется тестом 03; если подрядчик привозит important — он попадает в ранний слой, где для important-порядка ранний = сильный, поэтому такие правила требуют ревью и явной переписи, а не механического переноса.

## Последствия и риски

- Подключение новой команды/библиотеки: новый CSS обязан быть импортирован в ранний слой; unlayered-импорт снова даст ему приоритет над всей библиотекой. Регрессия обнаруживается статическим тестом (регэксп на `@import` без `layer(`) и e2e-тестом «primary button uses theme tokens».
- Смена порядка слоёв — несовместимое изменение для потребителей: любые правки `@layer reset, legacy, …` требуют нового ADR.
- `states` позже `components` означает: state-правила не обязаны знать специфичность вариантов (0-1-0 достаточно). Обратная сторона — глобальное правило в `states` по-прежнему может задеть все семейства, поэтому слой ограничен селекторами своего префикса `.ui-*` + псевдоклассов.
- Браузеры без `@layer` (до 2022) получат порядок импортов как fallback — приемлемо для evergreen-стенда.

## Два контрпримера

1. **Почему `!important` — не решение.** В baseline `#workbench .ui-button.is-danger { background:#a41e24 !important }` из vendor ломало hover-danger и тему: important-декларации сравниваются **до** normal, и «ответный» important из библиотеки только эскалировал бы гонку вооружений, делая приоритет непереносимым в другой контекст (вложенность, тема, другой vendor). Устранение important + изоляция слоя вернули управление токенам без единого повышения специфичности.
2. **Где одного `@layer` недостаточно.** (а) `display:none` у чекбокса переключателя — правило в любом слое исключит элемент из tab-порядка; лечится паттерном visually-hidden. (б) `dialog.show()` — слой не делает окно модальным; нужен `showModal()`. (в) Преждевременный `:invalid` — источник состояния (псевдокласс валидации значения) не совпадает с UX-состоянием «ошибка после взаимодействия»; нужен управляемый `aria-invalid`. (г) Горизонтальный overflow — причина в фиксированных `min-width` детей, а не в приоритетах.
